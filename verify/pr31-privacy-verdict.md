## 1. Claims that are wrong, unsupported, or overstated

1. **The signup function does not address the operator mailbox.** The draft says that if `ALERT_EMAIL` is unset, the signup and Stripe handlers address `jones.augie1@gmail.com` (`scoresnap/docs/privacy-policy.md` gap 10, citing `scoresnap/supabase/functions/on-user-signup/index.ts:11` and `scoresnap/supabase/functions/stripe-webhook/index.ts:11`). Stripe does: the webhook sets `to: ALERT_EMAIL` (`scoresnap/supabase/functions/stripe-webhook/index.ts:30`). Signup only declares the constant (`scoresnap/supabase/functions/on-user-signup/index.ts:11`). That identifier is not used anywhere else in the file. Signup mail goes to the new user and, at three referrals, to the referrer (`scoresnap/supabase/functions/on-user-signup/index.ts:38`, `168`).

2. **Cloud OCR runs in more cases than the draft states.** The draft says the photo is sent to Claude when ML Kit returns players at average confidence below 0.7, or when ML Kit is missing, fails, or throws (`scoresnap/docs/privacy-policy.md` gap 6 and the OCR section, citing `scoresnap/src/services/ocr-service.ts:18`, `69-115`). The early return that skips Claude also requires at least two players (`scoresnap/src/services/ocr-service.ts:55-57`). A one-player result is sent to Claude even when confidence is at or above 0.7 (`scoresnap/src/services/ocr-service.ts:70-73`). A successful ML Kit result with zero players does not throw; execution falls through to Claude (`scoresnap/src/services/ocr-service.ts:112-115`). The cited range contains those calls. The prose understates when a scorecard photo leaves the device. The separate claim that “Auto Claude Vision” is not read by `scanScorecard` is supported: the toggle is stored (`scoresnap/src/stores/settings-store.ts:33`, `65`; `scoresnap/app/settings.tsx:552-557`) and `scanScorecard` never reads it.

3. **Session replay is described as if names, scores, and scorecard photos are in the recording.** `Sentry.mobileReplayIntegration()` is called with no arguments (`scoresnap/app/_layout.tsx:51`). That part of the draft is right, and the repo does not pass a mask option. The pinned SDK is `@sentry/react-native` 8.4.0 (`scoresnap/package-lock.json`). That version’s `MobileReplayOptions` documents `maskAllText`, `maskAllImages`, and `maskAllVectors` as defaulting to true (https://cdn.jsdelivr.net/npm/@sentry/react-native@8.4.0/dist/js/replay/mobilereplay.d.ts). Sentry’s data-collected page says the Session Replay SDK masks text, images, webviews, and user input by default (https://docs.sentry.io/platforms/react-native/data-management/data-collected/). The label draft goes past the code when it says replay can include a scorecard photo, names, and scores, and when it says “Do not answer that replay is masked” (`scoresnap/docs/app-store-privacy-labels.md`, Other Diagnostic Data). The policy sentence “this repository does not show a mask” is literally true and is easy to read as “the recording is unmasked.” The SDK default is the opposite.

4. **The Sentry init list omits `enableLogs: true`.** The init block sets `enableLogs: true` (`scoresnap/app/_layout.tsx:38`). The policy’s list of what that init sets does not mention it. Sentry documents `enableLogs: true` as the switch that sends log events to Sentry (https://docs.sentry.io/platforms/react-native/logs/). Application source does not call `Sentry.logger`. The flag is still an undisclosed part of the Sentry configuration. Inventory row 12 lists exceptions, traces, navigation, replay, and feedback, not logs.

5. **The course-search cache key is not only the typed query.** The label says the cache is keyed by the query text (`scoresnap/docs/app-store-privacy-labels.md`, Search History, citing `scoresnap/supabase/functions/course-data/index.ts:50-74`, `115`). For a text search the stored key is `search.toString()`, which includes the normalized query plus `limit` and any coverage filter (`scoresnap/supabase/functions/course-data/index.ts:67`). The key is still not the user id. That part of the claim holds.

## 3. App Store label mapping

Apple’s form, for each collected type, asks linked to identity, used for tracking, and purposes. “Collect” means transmitting data off the device so the developer or a third-party partner can access it for longer than it takes to service the request. Tracking means linking that data with third-party data for advertising or advertising measurement, or sharing it with a data broker. Data stays “linked” unless identifiers are stripped before collection and are not put back afterward. In-app messages that are not SMS are still “Emails or Text Messages.” IP address is declared as the type that matches how it is used (precise location, coarse location, device ID, or diagnostics).

## 4. Absolute language and placeholders

No fix. The phrases “on-device only”, “no tracking”, “never share”, and “encrypted” are not used as blanket product claims.

- Contest storage: the draft says this repository does not show application-level encryption of contest data, and that `ITSAppUsesNonExemptEncryption: false` (`scoresnap/app.json:21`) is an export flag. That matches the file.
- Tracking: “No” is limited to this source tree and is followed by the vendor-dashboard warning (`scoresnap/docs/app-store-privacy-labels.md` opening).
- Location and ML Kit: coordinates are described as in-memory and not attached to the search request. The ML Kit wrapper has no network call, and the draft separately says it cannot tell whether the native binary contacts Google (`scoresnap/docs/privacy-policy.md`, “What I could not determine”).
- Support contact and support URL are `[SUPPORT CONTACT — owner to provide]` and `[SUPPORT URL — owner to provide]` (`scoresnap/docs/privacy-policy.md`, Contact). Nothing is substituted. `jones.augie1@gmail.com` is quoted from the webhook default and from the fact that `eas.json` contains an Apple ID (`scoresnap/eas.json:38`, `45`); the draft says that mailbox is not the support contact. The welcome HTML names “ScoreSnap by Autumn8me, Inc.” (`scoresnap/supabase/functions/on-user-signup/index.ts:69`). The draft does not adopt that string as the controller or the contact.

## 5. Listed gaps

1. **Account deletion does not delete server data. Real.** The alert says the action permanently deletes the account and all rounds, scores, statistics, and settings (`scoresnap/app/settings.tsx:226-229`). The handler removes five AsyncStorage keys and then calls `signOut` (`scoresnap/app/settings.tsx:247-256`). The removed scan key is `snapscore-scan`. The scan store key is `snapscore-scans` (`scoresnap/src/stores/scan-store.ts:66`). `snapscore-guest` (`scoresnap/src/stores/guest-store.ts:13`), `snapscore.chat.session.v1`, and `snapscore.chat.name.v1` (`scoresnap/src/services/live-chat.ts:6-7`) are not in the list. The TODO at `scoresnap/app/settings.tsx:254-255` says a Supabase `deleteUser` call is still to be written. There is no delete of `profiles` or the other server tables in that handler. `signOut` clears the in-memory auth session, calls `resetAll`, and both stores persist (`scoresnap/src/stores/auth-store.ts:220-232`, `239-247`; `scoresnap/src/stores/contest-store.ts:352-355`). That rewrites `snapscore-auth` and `snapscore-contests` after the wipe. The rewritten contest state is the reset state, not a silent restore of the old contests.

2. **`stripe-webhook` does not verify signatures. Real.** `STRIPE_WEBHOOK_SECRET` is read (`scoresnap/supabase/functions/stripe-webhook/index.ts:10`) and never used. The `stripe-signature` header is stored in `sig` (`scoresnap/supabase/functions/stripe-webhook/index.ts:55`) and never used. The following lines are a comment plus `JSON.parse` (`scoresnap/supabase/functions/stripe-webhook/index.ts:54-63`). The parsed event is then written to `revenue_events` and can be emailed (`scoresnap/supabase/functions/stripe-webhook/index.ts:68-80`, `108-114`).

3. **Sentry sends PII. Real as a setting. “Unmasked replay” is not what this SDK does by default.** `sendDefaultPii: true` is set (`scoresnap/app/_layout.tsx:37`). Sentry’s data-collected page says that flag is what turns on headers, cookies, logged-in user fields where an integration provides them, and the Android device name, and that IP is inferred from the connection unless the client overrides it. The draft is right that this repo does not list the exact fields and does not call `Sentry.setUser`. Replay sample rates and the no-argument `mobileReplayIntegration()` call are real (`scoresnap/app/_layout.tsx:46-51`). The recording those defaults produce is masked text and images, not an unmasked scorecard. See section 1, item 3.

4. **Tournament sync writes tables the baseline does not define. Real, and broader than the draft states.** The client writes `contest_rounds`, `contest_groups`, `contest_players`, `hole_scores`, and `contests` (`scoresnap/src/services/tournament-sync.ts:24`, `57`, `99`, `146`, `173`). Active migrations create `contest_players` and `contests` (`scoresnap/supabase/migrations/20261027000000_live_baseline.sql:38-68`) and do not create `contest_rounds`, `contest_groups`, or `hole_scores`. `scoresnap/supabase/migrations/20261027120000_sync_foundation.sql:1` says it adds no round or group schema. Copies of those tables exist only under `scoresnap/supabase/archive/pre-baseline/`, which is not an active migration. The draft names the missing `contest_rounds` and `hole_scores` tables and does not say `contest_groups` is missing too. Tables that do exist still do not match the payload: `contest_players` has no `sort_order`, `status`, or `course_handicaps` (`scoresnap/supabase/migrations/20261027000000_live_baseline.sql:38-48` versus `scoresnap/src/services/tournament-sync.ts:112-121`), and `contests` has no `is_tournament` or `current_round` (`scoresnap/supabase/migrations/20261027000000_live_baseline.sql:51-67` versus `scoresnap/src/services/tournament-sync.ts:174-176`). The client writes `hole_scores` and does not write the `score_events` table the baseline does create (`scoresnap/supabase/migrations/20261027000000_live_baseline.sql:255`).

Other gaps in the draft’s owner list, checked against the same commit and holding up: no retention delete for accounts, scores, chat, profiles, marketing events, or revenue events (share expiry is `infinity` until completion, then seven days, and rows are updated rather than deleted, `scoresnap/supabase/migrations/20261027000000_live_baseline.sql:507-510`, `707-708`, `736`, `776`); privacy and notification toggles are stored and not read by feature code (`scoresnap/src/stores/settings-store.ts:33-42`); there is no notification SDK in `scoresnap/package.json`; anonymous sign-in is off in local config (`scoresnap/supabase/config.toml:51`) and `signInAnonymously` does not appear in application source; skip sign-in writes a local `anon-<timestamp>` profile (`scoresnap/src/stores/auth-store.ts:206-217`); Turnstile runs only when captcha mode is `optional` or `required` (`scoresnap/src/config/captcha.ts:8-10`); `RECORD_AUDIO` is declared and unused; course search does not send coordinates.
