### 3. Referral tokens

`purge_replace_referral` takes the text after `Referral:` or `Code:` up to whitespace or `|`, strips trailing commas and semicolons, and replaces the value only when that whole token equals the caller's code (`20261028223000_account_purge.sql:85-134`). Properties and `campaign` use equality (`:331-338`). The automation_log update writes the function result only when it changes the row (`:339-343`).

`purge-account.sql` ran these assertions on PostgreSQL 17.11 and passed:

- `Code: SS-AUG10` against code `SS-AUG1` stays `Code: SS-AUG10`
- `Code: SS-AUG100` against code `SS-AUG10` stays `Code: SS-AUG100`
- `Referral: friend.ref | Code: SS-AUG10` against code `friend.ref` becomes `Referral: [deleted] | Code: SS-AUG10`
- a full `purge_account` of the user whose code is `SS-AUG10` rewrites that code to `[deleted]` and leaves stored `Code: SS-AUG1`, `Code: SS-AUG100`, and `Referral: friend.ref`

A second local database, built with the same migrations, purged a user whose code is `SS-AUG1`. `properties.referred_by`, `properties.referral_code`, and `campaign` equal to `SS-AUG1` became null. `SS-AUG10` stayed on `referred_by`, `referral_code`, and `campaign`. `SS-AUG100` stayed on `referred_by` and `campaign`. `friend.ref` stayed on `referred_by`. Log lines `Code: SS-AUG10`, `Code: SS-AUG100`, and `Referral: friend.ref | Code: SS-AUG10` stayed. `Code: SS-AUG1` became `Code: [deleted]`.

A third local database purged a user whose code is `friend.ref`. `Referral: friend.ref | Code: SS-AUG10` became `Referral: [deleted] | Code: SS-AUG10`. `Referral: friend.ref.extra`, `Code: SS-AUG10`, and `Code: SS-AUG100` stayed. Properties and `campaign` equal to `friend.ref` were cleared, and the unrelated `note` stayed. `SS-AUG10` and `SS-AUG100` on another event stayed.

The in-memory path used by the Jest scenario uses the same whole-token compare (`scoresnap/supabase/functions/delete-account/purge.ts:126-132`). Signup still writes `Referral: <value> | Code: SS-XXXX` (`scoresnap/supabase/functions/on-user-signup/index.ts:201`). The label itself is matched as the substring `Code:` or `Referral:`. In the `SS-AUG1` session, `MyCode: SS-AUG1 stays` became `MyCode: [deleted] stays`. That line is not the signup shape, and it does not change `SS-AUG10`, `SS-AUG100`, or `friend.ref`.
