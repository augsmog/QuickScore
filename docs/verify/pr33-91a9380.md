## Must-fix

1. A joined player's name stays on a surviving contest. `decide_join_request` clears `contest_players.user_id` and stores the account on `contest_memberships.player_id` (`scoresnap/supabase/migrations/20261027120000_sync_foundation.sql:129-131`). `purgeAccount` builds the name list only from `contest_players.user_id` (`scoresnap/supabase/functions/delete-account/purge.ts:137-142`). `listMemberUserIds` selects `user_id` and drops `player_id` (`scoresnap/supabase/functions/delete-account/supabase-repo.ts:63-66`). After a successful purge the roster `name`, snapshot `displayName`, and a matching chat `display_name` are unchanged. The same filter misses the owner: signup never writes `profiles.display_name`, `getProfile` loads it and `purgeAccount` never reads it (`purge.ts:113-115`), and `HOST_SLOT` blocks an owner membership (`20261027120000_sync_foundation.sql:121`). When another account keeps the contest, the owner's null-`user_id` roster row and published name stay. Settings still says the shared-round name becomes "Deleted player" (`scoresnap/app/settings.tsx:696`). A stand-in call of `purgeAccount` with `user_id: null` on the roster row and both users in `listMemberUserIds` left `namesPassed` empty and left `Augie` on the player, snapshot, and chat.

2. The referral code survives deletion. `clearReferralReferences` nulls only `profiles.referred_by` and `marketing_events.campaign` (`scoresnap/supabase/functions/delete-account/supabase-repo.ts:217-221`). Signup also writes that code to `marketing_events.properties.referred_by` (`scoresnap/supabase/functions/on-user-signup/index.ts:193`) and to `automation_log.details` as `Referral:` and `Code:` (`on-user-signup/index.ts:201`). `scrubAutomation` replaces the email and leaves the code (`supabase-repo.ts:210-213`). The same stand-in purge nulled the two columns and left `properties.referred_by` as `SS-AUG1`, the caller's log as `Code: SS-AUG1`, and the other account's log as `Referral: SS-AUG1`.

3. Android is not CAMERA-only. `app.json` lists only `android.permission.CAMERA` and sets `recordAudioAndroid: false` (`scoresnap/app.json:33-35`, `scoresnap/app.json:48`). That flag only stops the Expo config plugin from adding a second `RECORD_AUDIO` entry (`node_modules/expo-camera/plugin/build/withCamera.js:15-19` at expo-camera 17.0.10). The library manifest still declares it (`node_modules/expo-camera/android/src/main/AndroidManifest.xml:3`). Expo removes a third-party manifest permission only through `android.blockedPermissions` (`node_modules/@expo/config-plugins/build/android/Permissions.js:83-100`). `app.json` does not set that. The same plugin writes `NSMicrophoneUsageDescription` unless `microphonePermission` is `false` (`node_modules/@expo/config-plugins/build/ios/Permissions.js:29-35`); the plugin options do not pass `false`. `expo-file-system` also merges `READ_EXTERNAL_STORAGE` and `WRITE_EXTERNAL_STORAGE` (`node_modules/expo-file-system/android/src/main/AndroidManifest.xml:3-4`), and those are not blocked either.

4. A missing access token is treated as a successful server delete. `deleteServerAccount` returns without throwing when `getSession()` has no access token (`scoresnap/src/services/delete-account.ts:12`). `performAccountDeletion` then wipes the device (`scoresnap/src/services/account-deletion.ts:12-13`), and Settings replaces to onboarding (`scoresnap/app/settings.tsx:233-238`). The Supabase session lives in SecureStore (`scoresnap/src/db/supabase.ts:46-48`), separate from the persisted Zustand user. A signed-in device whose `getSession()` is empty keeps every server row and shows a completed deletion. The offline return at `delete-account.ts:10` is a different case: real auth is off, so there is no server account.

## What held

`handleDeleteAccount` discards the body, ignores the query string, and purges only `getUser().id` after a UUID check (`scoresnap/supabase/functions/delete-account/handler.ts:29-37`). `config.toml` sets `verify_jwt = true` for this function (`scoresnap/supabase/config.toml:61-62`). `getUser` is `auth.getUser(token)` with the anon key (`scoresnap/supabase/functions/delete-account/index.ts:19-21`), not a local JWT decode. A missing token, a failed `getUser`, or a non-UUID subject returns 401 and does not purge. `auth.admin.deleteUser` runs only after purge, with that same id (`handler.ts:36-37`, `index.ts:31`).

`publishedName` is `trim().slice(0, 80)` (`purge.ts:41-43`). Snapshot `displayName` and chat `display_name` are compared after that cut (`purge.ts:55-57`, `purge.ts:71-72`). `anonymizeSnapshots` selects every `published_rounds` row for the contest and updates each one (`supabase-repo.ts:82-94`). Those steps do not run for a name the purge never collects, which is must-fix 1. PostgREST still caps an unbounded select at 1000 rows, so a contest past that cap would keep later snapshot or chat rows. Message bodies are left on purpose (`scoresnap/docs/account-deletion.md:42`).

`sentrySendDefaultPii` is `false`. `sentryReplayMask` sets `maskAllText`, `maskAllImages`, and `maskAllVectors` to `true` (`scoresnap/src/config/sentry-privacy.ts:10-16`). Those three fields exist on `MobileReplayOptions` in `@sentry/react-native` 8.4.0 and default to true. Init passes them (`scoresnap/app/_layout.tsx:41`, `scoresnap/app/_layout.tsx:55`). `scrubSentryEvent` keeps `{ id }` only (`sentry-privacy.ts:39-44`). No `Sentry.setUser` call site was found under `scoresnap/`.

`handleStripeWebhook` reads `req.text()` and verifies before `processEvent` (`scoresnap/supabase/functions/stripe-webhook/handler.ts:11-15`). A missing secret, missing signature, invalid HMAC, or stale timestamp returns HTTP 400 (`verify.ts:24-32`). Tolerance is 300 seconds (`verify.ts:1`). `verify_jwt` is false for this function (`config.toml:64-65`), which is required because Stripe does not send a Supabase JWT. The signature check is the gate. `sk_test_placeholder` is used only to construct the SDK when `STRIPE_SECRET_KEY` is unset (`index.ts:17`). It is not the webhook secret.

`git diff --check` from `92b6c9b` to `91a9380` exited 0. The diff has no `sk_live`, no live `whsec_`, no service-role JWT, and no private key. `whsec_test_only_not_a_real_secret` is only in `scoresnap/tests/stripe-webhook.scenario.ts`. The Sentry DSN in `app/_layout.tsx` is not part of this diff.
