### A. Architecture and Free-plan envelope

Options: Postgres Changes streams of base rows; database-triggered private Broadcast notifications; client Broadcast; Edge Functions as write gateway. Recommend **Postgres source of truth, SECURITY DEFINER RPC transactions, database-triggered private Broadcast of revision-only notifications**. RPC fetch supplies authorized snapshots; Broadcast is a hint, never the record. Postgres Changes is simpler initially but risks raw row exposure and per-subscriber authorization cost. Client Broadcast cannot durably arbitrate offline writes. Edge Functions add a deployment and invocation budget without improving atomic SQL score edits.

Use one multiplexed Realtime socket per foreground client, one active event channel and optional league notification channel. No presence/typing traffic. Subscribe acknowledgement followed by snapshot fetch closes the race; poll at 30 seconds only while foreground and notifications are unavailable. Viewer channel is scoped to a share session; player channel to event membership. No raw scores, identities, tokens or chat bodies in Broadcast.

Public limits checked **2026-10-26**: [Supabase Free](https://supabase.com/pricing) includes 500 MB database/project, 50,000 MAU, 5 GB egress plus a separate 5 GB cached allowance, 500,000 Edge Function invocations/month, two active Free projects and pausing after one week of inactivity. [Realtime Free](https://supabase.com/docs/guides/realtime/pricing): 200 peak connections and 2 million messages/month. Anonymous users count toward Auth usage. Remaining account/project capacity, current settings and paused-project eligibility remain **UNVERIFIED**; M0 saves Usage receipts. No automatic billing/Pro enablement.

Pilot estimate: 4–16 connected phones, 72 score writes per four-player 18-hole round; 4–16 notification deliveries/write ≈288–1,152 deliveries, plus sends/control messages, fetches, chat and retries. Measure pilot anonymous Auth user counts and auth.users/profile row and byte growth at baseline, after signup and daily (including abandoned guests); anonymous users lack automatic cleanup, so propose retention separately without deleting here. Record actual metering; this is not an exact Supabase bill formula. Audit payloads and avoid a perpetual five-second full-snapshot fanout. Local operating guard: investigate at 70% of any verified allowance; restrict new sharing before exhaustion, preserve outboxes and local scoring. No automatic upgrade.

**Verify before build:** box saves pricing/Usage timestamp and limits, Auth settings, schema dump and RPC definitions. Local CI proves committed writes emit notifications, rolled-back writes do not; outsider cannot subscribe; revoked member cannot fetch. Prototype private-channel revocation with an already connected socket: timeout/reconnect enforcement must not be assumed. If immediate disconnect cannot be enforced, revision-only hints remain non-sensitive and every data fetch/write still checks revocation; document measured disconnect behavior before shipping.

### C. Invite, links and codes

Options: custom scheme only; HTTPS universal links + web fallback; paid deferred-link provider. Recommend for the urgent path existing HTTPS host/Vercel web fallback + typed code, with explicit “Open SnapScore” using `snapscore://join/<code>` or `snapscore://r/<token>` from the verified web page. Automatic universal-link opening is scheduled for M10 by Augie’s staged-delivery decision; AASA/entitlement testing is required. QR encodes the HTTPS URL. No deferred deep linking: after install, reopen original message or enter code.

Reuse `/join/[code]`, `/join/enter` and `/r/[token]`; retain Back/Home on every state. Six-character alphabet is the exact `guest-join.ts` alphabet (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, 32 symbols, 30 bits). Generate server-side with cryptographic randomness, unique index and bounded collision retry, not Math.random/local array uniqueness. Six characters are a locator, not a player capability. Initial name selection and all occupied-slot transfers require host approval; before approval return generic pending-request status only, with no roster/scores. Requester supplies a name; host assigns/approves its slot. A separate high-entropy invite capability would be required for pre-approval roster display. Code-only public viewing would be an explicit Augie privacy decision, not part of this recommendation. Host can approve requests together.

Keep watch token separate: current 003 is 64 hex characters from two UUIDs, not 256 fully random bits. For new links use 32 CSPRNG bytes encoded as 64 hex, store only SHA-256 digest; retain old token validity until expiry/revocation. Possession allows viewing/chat, never score writes. Exchange token for short-lived identity-bound viewer session (maximum one hour, capped by link expiry); revalidate parent link on every snapshot/chat RPC. Maintain legacy RPC compatibility while removing privacy leaks.

Player invite links use code for discovery and host-approved membership for access. Codes active only while event accepts joining, expire no later than event end +7 days, can rotate/revoke independently of watch links. Watch links retain GS14 end +7 days rule; ongoing events can be manually revoked. Reissue cannot extend a completed event's end-based deadline. Revoke scoring invite stops new requests; removing a scorer separately revokes membership. UX distinguishes both.
