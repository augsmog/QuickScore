# Pending tournament completion API

This patch extends the unmerged M4b migration, not the production schema. It must be reviewed together with PR #50. Production apply still requires Augie's explicit yes.

`submit_group(contest_id, round_id, group_id, expected_revision)` requires a nonanonymous owner or an approved scorer with an approved scope for that exact group. It locks the contest before checking role, enabled state, revision, course, active assignments and complete scores. It records the group's current score and assignment revisions. Every accepted score change (including a clear) removes the group's submission; a stale revision must be refreshed and explicitly resubmitted.

`finalize_tournament(contest_id, expected_revision)` requires a nonanonymous owner and the same contest lock. Every round needs groups, every active player needs an assignment in each round, and every group needs a current submission from the owner or a still-authorized scorer. Revision mismatch, missing/stale submissions, pause or completion refuse the operation. Completion closes writes and freezes the published link deadline at seven days. A trigger denies direct client status transitions; existing RLS also prevents those updates.

The client submits only online, after a fresh authorized snapshot and two empty-queue checks. Its writer lock excludes concurrent local enqueue/resolve operations. Neither client nor server can detect another phone's unsent drafts: the explicit group confirmation and host finalization UI disclose this limitation. Lost-response completion is resolved by refreshing; it is never silently queued or automatically retried as a new finalization.

Join budgets return the same pending response for unknown/paused/limited codes. Private counters cap requests at five per identity/minute, sixty per event/minute and three hundred globally/minute (including unknown codes and fresh identities). These are fixed server-clock windows, so bursts can straddle a minute boundary. Score writes serialize an identity-wide rolling limit of 120 new operation receipts/minute; exact existing receipts still replay after reauthorization. Provider CAPTCHA/IP controls and production monitoring are separate release gates; these SQL tests do not certify provider configuration.

Proof entrypoints: `supabase/schema-drift/m4b-local.sh` applies the entire chain, checks catalog/ledger/ACLs, tests mutations and real two-session races, and rehearses exact down. `supabase/tests/m5-security.sql` covers private budgets, generic responses, recovery and write limiting. The client four-identities disposable-stack test additionally exercises production completion orchestration, late-write refusal and GS14 link-holder chat/moderation/rate/expiry behavior. Native-stack mode stubs Auth issuance and Realtime and cannot substitute for hosted real Auth/socket CI or physical phones.
